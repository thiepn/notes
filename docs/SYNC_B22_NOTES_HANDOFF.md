# Notes Sync B22 — actual saved-file inspection in original BackupWorkspace

The existing Notes device-switch UI still invokes the original SyncProvider and Account session refresh, and opens the unchanged original BackupWorkspace. B22 adds a real **Inspect a saved Notes backup for device switch** action *inside* that original workspace, reusing original BackupRepository.inspectBackup, Zod validation, attachment digest verification and the existing safe read-only selected-backup preview. It deliberately does not restore or export a different type of file. A saved file, selected by the user from their device, must be validated before presenting a device-handoff message. That message gives only validation status and warns that local file validation does not prove Account ownership, source record convergence, independent external storage, or retention. An inspect-generation fence prevents a slow older file validation from overwriting a newer file. Restore still requires the original explicit confirmation and safety download. The manual-backup timestamp in Settings remains device-local and unattributed; no private Notes contents or files are passed to Core or Hub. B22 adds pure unit and guest Chromium checks without touching production data. Real signed-in two-device and physical Android restoration NOT_TESTED; external custody NOT_TESTED.
