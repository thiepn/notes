# B26 Notes original Account/session and device-local sync lifecycle

Notes now supports owner-scoped device-local **Pause cloud sync** and **Resume original Notes cloud sync** in its existing Account & sync settings. Pause is persisted as a local preference bound to the original Notes Account owner ID (not a separate authentication, dataset, or permission service). It increments the original SyncProvider session epoch, blocks foreground/online/manual native sync while paused, and prevents previously launched original `syncEngine` results from publishing success after pause. Existing local IndexedDB notes, attachments, checklist items and revisions remain readable/editable. On resume Notes re-enters its original `activateSession` flow, checking authorized Account grant and using the original synchronizer; a stale session cannot be reauthorized by a toggle.

The original Account pages retain actual sign-in, password/token handling, other-device sign-out and global session revocation. Pause is **not** remote device revocation; that remains controlled by Account session actions. A storage-event owner/token switch already bumps the original epoch and rechecks grant. Original Core consent and Hub status remain separate. The B26 helper regression checks owner/generation/pause gates. Real two-device Account revocation NOT_TESTED; no remote data or production mutation.

The device-local pause preference is now keyed by its original Account owner, rather than one last-active-owner preference. Same-origin tab storage events invalidate a paused tab's original SyncProvider epoch before it can display a stale cloud confirmation. A resume re-enters the original Account authorization flow. Neither local preference is a remotely revoked device grant.
