# PWA + Offline Certification

P15 certifies Notes as an installable, local-first PWA at the production base path `/notes/`.

The phase does not introduce a cloud sync layer. Notes remains an IndexedDB application whose core note operations must work without a network connection.

## Installability contract

The generated web app manifest must provide:

- stable app identity: `/notes/`
- `start_url`: `/notes/`
- `scope`: `/notes/`
- standalone display mode
- 192×192 PNG icon
- 512×512 PNG icon
- 512×512 maskable PNG icon

Browser metadata also includes a 32×32 favicon and 180×180 Apple touch icon.

The app is not allowed to register a service worker outside `/notes/` or claim unrelated pages on the parent domain.

## Service-worker policy

Notes uses the Workbox service worker generated by `vite-plugin-pwa`.

The production registration policy is deliberately conservative:

- initial install precaches the production app shell
- navigation under `/notes/` falls back to the precached Notes shell
- outdated generated caches are removed
- a new service worker does not force an active editing session to reload
- when an update is waiting, the UI offers an explicit **Reload** action
- dismissing the update leaves the current version running until a later reload/update opportunity

This protects local drafts and avoids surprising reloads during capture or editing.

## Offline behavior

After the service worker has completed its first online installation, Notes must support all of the following with network access disabled:

1. cold reload `/notes/`
2. render the application shell
3. read existing IndexedDB notes
4. create a new text note
5. persist the new note locally
6. cold reload again
7. show both the pre-existing and newly-created offline note

The offline indicator is informational. It does not disable note creation, editing, organization, search, history, backup access, or other operations whose data already exists locally.

Features that inherently require the user to choose external files can still be initiated offline because file selection and parsing are local browser operations.

## Update UX

A waiting service-worker update produces a compact status surface:

- **Update available**
- **Reload** applies the waiting worker and reloads
- dismissing the prompt does not reload or discard local state

Notes does not use silent forced reloads for PWA updates.

## Install UX

Where Chromium exposes `beforeinstallprompt`, Notes defers the native prompt and surfaces an opt-in **Install Notes** action.

Dismissal has no effect on Notes data or ordinary browser use. Browsers and platforms that do not expose this event continue to work normally and may use their own installation UI.

## Offline-ready and failure states

When the first production service worker finishes preparing the app shell, Notes briefly reports **Ready offline**.

If service-worker registration fails, Notes reports that offline setup is unavailable. The application itself remains usable while the currently loaded page is open because note data is still stored locally in IndexedDB.

## Production-only certification

Normal Playwright regression tests use the Vite development server and do **not** certify PWA behavior because the production service worker is not the same runtime.

P15 adds a separate Playwright configuration that runs against `vite preview` after `npm run build`.

The production PWA test verifies:

- manifest discovery
- exact app identity/start URL/scope
- 192×192 and 512×512 install icons
- maskable icon declaration
- icon files are actually served
- service-worker activation
- service-worker scope is exactly `/notes/`
- offline cold reload
- existing-note read while offline
- new-note write while offline
- second offline reload with both notes intact
- deferred install prompt can be dismissed safely

CI runs this suite after the normal unit/build/browser regression gate.

## Base-path rule

All PWA URLs must remain compatible with the production target:

```text
https://thiepn.dev/notes/
```

The Vite base, manifest identity, scope, start URL, icon URLs, and navigation fallback therefore all use `/notes/`.

A root-scoped service worker (`/`) is a release blocker because it could interfere with other applications hosted on the same domain.

## Deployment boundary

GitHub Pages deployment is a separate repository-hosting concern from the PWA runtime itself.

The deployment workflow builds `dist/`, configures Pages, uploads the Pages artifact, and deploys it through the official GitHub Pages actions.

If Pages has never been enabled for the repository, GitHub requires a one-time repository configuration (Settings → Pages → Source: GitHub Actions) unless a sufficiently privileged non-`GITHUB_TOKEN` credential is supplied to `actions/configure-pages` for automatic enablement.

P15 does not add a privileged token or weaken repository security merely to bypass that one-time setting.

## Release gate

P15 is certified only when all of these pass on the same PR head:

```text
format
lint
typecheck
unit tests
production build
normal Chromium regression suite
production PWA/offline certification
```

After merge, main CI must pass again. If GitHub Pages is enabled, the Pages deployment must also complete successfully before the hosted build is considered production-verified.
